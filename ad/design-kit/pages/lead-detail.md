# Enquiry detail

**Route:** /admissions/leads/:id. **Primary action:** contextual task, not generic status editing.

Header: breadcrumb, student name/grade, current stage. Avoid a full process ribbon by default. Parent contact and next commitment follow immediately. Desktop main area plus 300px next-action rail; mobile moves next action above history.

Main content: Activity and Details tabs. Activity shows last conversation, note composer and recent chronological events. Use named events and actor/date; older events behind View older activity. Details groups student, guardian and enquiry facts; section-specific Edit buttons avoid a wall of editable inputs.

Rail: next action, absolute appointment/timezone, requested-by-parent indicator, owner and one permitted action. Responsible team changes visibly after handover. Historical caller remains in details, not as a competing current owner.

Clerk can request a callback and add an internal note. Caller can record an outcome. Manager can reassign. Test/admissions staff see stage-specific actions. Internal notes never send parent messages.

Closure/reopen dialogs show reason and task effects. Concurrent edit preserves draft and asks for review. Test long history, no action, closed opportunity, direct test entry and role changes. Current next step must be understood without scanning the whole timeline.
