# Acceptance checklist

## Specification
- [ ] Relevant page brief and shared states read.
- [ ] No contradictory token values or unverified brand claims.
- [ ] Permissions and actual primary action identified.

## Visual
- [ ] One clear task and primary action; secondary controls subordinate.
- [ ] No unnecessary metrics, nested cards, gradients or repeated badges.
- [ ] Actual logo asset or explicitly labelled prototype placeholder.
- [ ] Text readable; long names/notes and 200% zoom handled.
- [ ] Colour pairs meet required rendered contrast; icons/text carry state.
- [ ] Desktop, tablet and mobile reviewed with evidence.

## Interaction
- [ ] Callback context remains visible during outcome entry.
- [ ] Conditional fields avoid unnecessary choices.
- [ ] Failed save preserves draft and active lead.
- [ ] Conflict/reassignment/session expiry have recovery paths.
- [ ] Keyboard focus, dialog return focus and form errors work.
- [ ] No nonfunctional or misleading controls.

## Staff test
- [ ] Clerk captures a new enquiry and detects a repeated one without coaching.
- [ ] Caller schedules a requested callback and finds next work without coaching.
- [ ] Staff can recover from a failed save and identify saved versus unsaved work.
- [ ] Observed hesitation/errors recorded; changes retested.

Record evidence in review-log.md. Unchecked items remain pending; a specification alone does not satisfy runtime or staff-test checks.
